## Before the link goes to any creator

The page is built with clearly marked placeholders, but it must not be sent until everything below is settled. `npm run presend` (added in the build) fails while any `[FILL]` placeholder remains or any open input is not ticked as confirmed.

**Open inputs (PRD section 8):**

1. The weekly commitment asked of creators (Block 6).
2. The launch-timing answer (Block 7, FAQ).
3. The content-ownership answer, confirmed against the terms (Block 7, FAQ) - or remove the question.
4. The footer legal / contact line (Block 8). Does not block sending.
5. ~~The Instagram handle the button opens, and the deploy domain. The placeholder is `riffi`; it must be confirmed as Riffi's real account.~~ **Confirmed 17 Sep 2026:** handle is `get.riffi`, domain is `https://riffi-creator-page.vercel.app` (live). No longer blocks sending; `npm run presend` reflects this - it now lists only items 1-4 above (as four `[FILL]` markers plus their four matching `inputsConfirmed` flags, eight problems in total).

**Questions from the product review (14 Sep 2026):**

6. **Which inbox.** *(Partly changed 17 Sep 2026: the button no longer opens a DM at all - see item 13 and `docs/technical-spec.md` "Links".)* Do Zyra's outreach DMs, and the replies the helper line promises from `@get.riffi`, come from the same account creators would separately message? The original risk (yeses split across two inboxes) becomes: does anyone monitor the Google Form responses as reliably as a DM inbox, and does the "@get.riffi" reply promise still hold now that the button's own destination is a form, not that account?
7. ~~**Preview card.** Set the domain before the first send - the card needs it, and Instagram caches previews.~~ **Done 17 Sep 2026:** `settings.siteUrl` is the live domain and the built preview card is built from it - see `docs/technical-spec.md` "Deploy". Because the page is reachable at that real URL already, any crawler (Instagram included, the moment a link is shared) can now cache this card - treat it as already "sent" for caching purposes even before the founder's first DM.
8. **Commitment vs launch.** Inputs 1 and 2 must agree, and must say where creators can post before launch and what happens after "I'm in" - or, since 17 Sep 2026, after the form is submitted.
9. **The 51st yes.** "Claim a seat" meets the FAQ's "we're picking for takes". Decide what an over-subscribed yes hears, and what the page says when batch one is full. *(The mechanism changed 17 Sep 2026 - a form submission, not a DM reply - but the open question is the same.)*
10. **"The front page."** Block 3 promises every first post the front page - it must be true for all 50.
11. **End-to-end proof.** *(Updated 17 Sep 2026: the conversion is now a form, not a DM.)* Open the final link on a test account that does not follow Zyra, on a real Android and a real iPhone, through to a submitted form response - and separately confirm a real reply arrives from `@get.riffi`, since the page now promises that as a second step rather than as the conversion itself.
12. **Did it help.** From the first send, log every link sent, every form submission and every question asked. The yes-rate is the signal; a question that keeps coming up is a gap on the page.

**From the safety reviews of the build plan (14 Sep 2026):**

13. **One way online.** The page goes online only through `npm run release`, which builds it, checks what the built page loads and links to, and refuses while any open input above is unconfirmed or the preview card still points at a placeholder address. Never deploy a bare build, and never put an early build online where it can be shared - Instagram keeps the first preview card it sees. **Flagged 17 Sep 2026, this session:** the page is now live at `https://riffi-creator-page.vercel.app` (commit `8805192`), but `npm run presend` reports eight open problems today (items 1-4 above) and there is no `vercel.json` or recorded project setting pointing Vercel's build at `npm run release` rather than the default `npm run build` - so this rule cannot be confirmed to have been followed for this deploy, and the live page may currently be showing unconfirmed placeholder text (the Block 6 commitment and two FAQ answers) to anyone who reaches it directly, not only to a creator who was sent a reviewed link. Worth the founder's explicit confirmation of how the deploy was configured, before relying on this rule again.
14. **Raise the stage at first send.** Before the first link goes out, change Zuko's stage from "before launch" to "early", and mark the content file, the link file, the page head and the preview images as not reversible: once a creator has read a promise, changing it is no longer a quiet fix. **Not yet done:** `CLAUDE.md`'s `maturityTier` is still `prelaunch` as of this update, even though the page is already reachable at a real, indexable URL (see item 13).
15. **Legal check (India's DPDP Act).** Get a legal review before sending: creators under 18 need verifiable parental consent before their data is used; a privacy notice and a grievance contact may be required; and if the WhatsApp option is switched on, its number becomes public. *(17 Sep 2026: the primary conversion is now a Google Form, which itself collects creator data - confirm this review covers form responses, not only DM replies.)*
16. **The WhatsApp label.** "Or message us on WhatsApp" is the build's own wording, not PRD copy. The founder signs it off before WhatsApp is switched on.
17. **Known limits to accept or fix.** The ₹ sign is not in the fonts' Latin files, so it shows in the phone's own font - moot today since no ₹ figure remains on the page (17 Sep 2026; see the drift log). The styling needs iOS Safari 16.4 or newer; older iPhones get a plainer page.

Plus: the brand kit (logo, colours, typefaces) arrives separately. The swap is `tokens.css` plus one wordmark SVG.
